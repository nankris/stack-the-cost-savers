# Output rules
- Be terse. No preamble, no recap, no closing summary.
- Don't explain what you're about to do; just do it.
- Don't restate the task or the code back to me.
- Read only the files you need. Prefer one targeted command over many exploratory ones.
- Make the smallest change that fixes the problem. Don't refactor or reformat unrelated code.
- Run the relevant test once after the change. Don't re-run it if it passed.
- Final reply: one line saying what you changed, max 20 words.
- Never edit tests to make them pass.
- If something is ambiguous, pick the most likely reading and note it in one short line.
